# 설계: check-docs 플레이스홀더 검출 고도화 + 회귀 테스트

## 문제 / 목표

다른 세션의 실사용 피드백: `check-docs.sh`의 플레이스홀더 정규식이 4개 패턴
(`[프로젝트명]`·`[개요]`·`[스택/호환버전]`·`YYYY-MM-DD`)만 봐서 `[설치 명령]`·
`[한두 줄: …]`·`VAR_NAME`을 통과시켰고, **거짓 초록불**을 6번 냈다. 사용자 가이드 미작성이
게이트에 잡히지 않았다. 검출을 넓히되 오탐 없이, 그리고 회귀를 테스트로 고정한다.

## 설계

- **검출 규칙 재설계**: 스켈레톤 플레이스홀더는 전부 한글(비-ASCII)을 포함한다는 관찰을 이용해
  **비-ASCII 문자를 포함한 대괄호**(`\[[^]]*[^ -~][^]]*\]`)를 플래그. + `VAR_NAME`·`YYYY-MM-DD`·
  `HH:MM`·ID 리터럴(`-NNN/-NN/-N-M`). 체크박스(`[ ]`/`[x]`)·`[Unreleased]`·코드 인덱싱(`arr[idx]`)은
  ASCII라 자연히 제외.
- **Mermaid 펜스 제외**: `docs/how-it-works.md`의 노드 라벨(`[집계 엔진]`)이 비-ASCII 대괄호라
  플레이스홀더와 구분 불가 → ```mermaid 펜스를 빈 줄로 치환(행번호 보존)해 검사 대상에서 뺀다.
  다른 코드펜스의 `[설치 명령]`류는 남겨 검출.
- **로케일 독립**: `[^ -~]` + `LC_ALL=C` 로 비-UTF-8 CI에서도 동일 동작(한글 범위 `[가-힣]`은 불안정).
- **제외**: 마크다운 링크/이미지(`](`)·각주(`[^`).
- **회귀 테스트**: `scripts/test-check-docs.sh` — 임시 대상 프로젝트를 만들어 정탐·오탐·Mermaid
  제외·strict 종료코드를 단언. CI에 스텝 추가.

## 검토한 대안

- 대괄호 판별: **비-ASCII 포함**(채택) vs 한글 범위 `[가-힣]`(기각: 비-UTF-8 로케일 불안정) vs 명시적 어휘 allowlist(기각: 피드백이 지적한 "빠뜨림" 재발).
- 코드펜스: **mermaid만 제외**(채택) vs 전체 코드펜스 제외(기각: `[설치 명령]`이 ```bash 안이라 놓침).

## 리스크 / 고려사항

- lazy 문서(how-it-works)를 안 쓰는데 스켈레톤을 남기면 경고 → 부트스트랩에서 미사용 lazy 문서는 삭제(-f 가드로 스킵).
- 검출 규칙은 스캐폴드 고유(글로벌 미러링 대상 아님).
