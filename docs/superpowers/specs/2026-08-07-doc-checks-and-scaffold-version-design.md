# 설계: 대외 문서 검사 2종(§8·§9) + 스캐폴드 버전 스탬프

## 문제 / 목표

파생 프로젝트 3종(`mobius4`, `mobius4-dev-tool`, `mobius4-browser`)을 쓰며 나온 요청 셋을
한 사이클로 처리한다. 셋 다 **실제로 사고가 났거나 이식을 시도했다 되돌린** 건이다.

### ① 릴리즈 버전이 대외 문서에 반영되지 않았다 (실측)

`mobius4` v4.10.0(파괴적 변경 포함)을 릴리즈하면서 `package.json`·`CHANGELOG.md`·git tag를
모두 4.10.0으로 맞췄다. 그런데 README 버전 이력 표에 4.10.0 행이 없었고, `docs/upgrading.md`·
`docs/how-to.md`도 빠져 있었다. 통합자가 가장 먼저 보는 곳이 README 버전 표인데 파괴적 변경을
알릴 문서가 비어 있었다. 사람이 눈으로 잡았다.

§6(버전 3자 일치)이 못 잡은 것은 정상이다 — 그 검사는 `SoT ↔ changelog ↔ tag` 셋만 보고
README는 대상이 아니다.

> **요청서와 어긋난 사실**: 요청서는 이때 `check-docs --strict`가 통과했다고 적었으나,
> `mobius4`에는 `scripts/check-docs.sh`가 없다(`.claude/`에 `settings.local.json` 하나뿐).
> 그 통과 기록은 다른 레포에서 나온 것이다. 사고 자체는 실물로 확인된다 — README 163~164행,
> `CHANGELOG.md:57`의 `## v4.10.0`, 태그 `v4.10.0`(4.10.0 행은 지적 후 채워진 상태).

### ② 필수 납품 문서가 없어도 통과한다 (자식 레포에서 이식했다 되돌린 건)

§1의 `REAL_DOCS`는 glob이라 **파일이 아예 없으면 조용히 건너뛴다.** "문서가 미작성"은 잡지만
"문서가 없음"은 못 잡는다. `mobius4-dev-tool`이 자체적으로 필수 문서 검사를 넣어 썼으나,
`mobius4-browser`에 상류 스캐폴드를 깔고 이식하자 `test-check-docs.sh`가 6건 실패해 되돌렸다.
원인은 픽스처가 그 문서들을 만들지 않는 것과, "더티 파일을 지우면 통과" 케이스와의 충돌이다.

### ③ 파생 레포가 자기가 받은 스캐폴드 버전을 모른다

스캐폴드는 `VERSION`(0.1.0)과 changelog를 갖지만, **복사되는 산출물 어디에도 출처 버전이
찍히지 않는다.** 그래서 파생 레포는 무엇이 최신인지 코드를 diff해서 확인하고 있다.

**목표**: 위 셋을 각각 §8 검사 / §9 검사 / 버전 스탬프로 해소하고, 세 변경을 담아 v0.2.0을
끊는다. 스탬프는 릴리즈가 있어야 의미가 생기므로 같은 사이클에 묶는다.

## 요구사항 연결

스캐폴드 자신이라 REQ/FR 문서는 골격 상태다(대상 프로젝트가 채움). `BACKLOG-004` ·
`DEC-017`(§8) · `DEC-018`(§9) · `DEC-019`(스탬프)로 추적하고, 검증은
`scripts/test-check-docs.sh`의 회귀 케이스가 담당한다.

## 설계

### ① §8 — 릴리즈 버전의 README 반영 검사

**판정**: *직전 릴리즈 버전이 README에 있는데 현재 버전(SoT)이 없으면* 경고.
둘 다 없으면 그 프로젝트는 README에 버전을 적지 않는 것이므로 **스킵**한다.

설정이 필요 없고, "버전을 README에 적는 습관이 있는 레포"에서만 켜진다. 이번 사고는
잡힌다 — README에 4.9.0은 있고 4.10.0이 없는 상태였다.

**직전 버전의 출처는 두 단계**다.

1. `changelog_previous_release()` — changelog에서 SoT와 다른 첫 릴리즈 헤딩
2. 1번이 비면 `previous_git_tag()` — semver 태그 중 SoT를 제외한 최댓값

changelog만 보면 `mobius4`처럼 changelog를 루트 `CHANGELOG.md`에 두는 레포에서 그냥 스킵되어
**정작 사고 난 레포를 못 잡는다**(`lib-version.sh`의 `CHANGELOG_PATH`는
`.claude/workspace/changelog.md`로 하드코딩). 태그를 폴백으로 두면 설정 없이 두 레이아웃을
모두 커버한다. 반대로 태그만 보면 태그를 안 다는 프로젝트에서 무력화된다.

> 초안에는 "스캐폴드 자신이 태그를 안 단다(v0.1.0 태그 없음)"고 적었으나 **사실이 아니다** —
> `v0.1.0` 태그는 `fc6fe48`에 이미 달려 있었다(확인 없이 단정한 것). 태그를 안 다는
> 프로젝트가 있다는 일반론은 그대로지만, 이 레포는 그 예가 아니다.

**스킵 조건** (하나라도 해당하면 검사하지 않음):
- `version-policy: none` 이거나 버전 SoT가 없음 (§6과 동일)
- `README.md`가 없음
- 직전 버전을 두 소스 어디서도 찾지 못함 (첫 릴리즈)
- 직전 버전이 README에 없음 (= 버전을 README에 적지 않는 프로젝트)

**알려진 한계** (스크립트 주석과 룰에 명시):
- 문자열 포함만 본다. 행이 있어도 내용이 비었으면 못 잡는다.
- 첫 릴리즈에는 비교 대상이 없어 동작하지 않는다.
- README에 `v1.2.0부터 지원` 같은 과거 버전 산문만 있고 현재 버전을 안 적는 레포에서는
  오탐한다. 현재 버전을 README 어디든 적으면 사라지는 자기해소형 경고다.
- 대상은 README 하나다. `docs/upgrading.md` 등으로 넓히면, 버전을 역사적으로 인용하는 문서
  (`v4.9.0에서 도입`)가 릴리즈마다 영구 오탐이 된다.

### ② §9 — 필수 납품 문서 존재 검사

**필수 2종만 둔다**: `README.md`, 그리고 `CLAUDE.md` **또는** `.claude/CLAUDE.md` 중 하나.

- CLAUDE.md를 두 위치 중 하나로 보는 이유: 스캐폴드 자신은 `.claude/CLAUDE.md`만 쓰고
  (`project-init.md`가 "`.claude/CLAUDE.md` ← (선택) 루트와 통합 가능"으로 규정), 파생 레포
  둘은 루트 `CLAUDE.md`를 쓴다. 한쪽만 요구하면 **스캐폴드 자신이 경고를 낸다**.
- `docs/user-guide.md`·`docs/how-it-works.md`는 **필수로 두지 않는다.** DEC-009가
  how-it-works를 **lazy 생성**(흐름 설명이 필요한 첫 큰 기능 완료 시)으로 규정했다. 필수로
  두면 자기 룰과 모순되고, 부트스트랩 직후 모든 프로젝트가 경고를 단다.

**들어가는 자리**: §1의 스캐폴드 자기감지 `else` 블록 맨 앞(`REAL_DOCS` glob 직전). 템플릿
레포 자신은 검사하지 않는다 — `_skeleton-README.md`가 있는 상태는 아직 부트스트랩 전이다.

**테스트 픽스처 보강** (이식 실패의 진짜 원인):
- `new_project()`와 첫 인라인 트리가 `README.md`·`CLAUDE.md`를 만들도록 한다.
- "더티 `how-it-works.md`를 **지우면** 통과" 케이스를 **"깨끗한 파일로 교체하면 통과"**로
  바꾼다. 의도(클린 문서만 남으면 통과)는 그대로면서 §9와 충돌하지 않는다.
- 누락 검출 전용 케이스를 추가한다.

### ③ 스캐폴드 버전 스탬프

`.claude/SCAFFOLD-VERSION` — 한 줄에 버전만. `.claude/`는 통째 복사되므로 파생 레포에
자동으로 따라간다. 파생 레포는 이 숫자와 업스트림 `VERSION`을 비교하면 되고, 무엇이 바뀌었는지는
업스트림 `README.md`의 Changelog와 `.claude/workspace/changelog.md`에서 본다(둘 다 이미
과거 이력을 담고 있다 — v0.1.0에 2026-06-30까지 백필됨).

**스탬프가 거짓말하지 않게 하는 두 장치**:
- `/release`(`new-release.sh`)가 버전 SoT와 함께 스탬프도 쓴다.
- `check-docs` §10이 **스캐폴드 템플릿 레포에서만** `VERSION`과 스탬프의 일치를 검사한다.
  파생 레포에서는 두 값이 다른 게 정상이므로(스탬프=받아온 버전, VERSION=자기 버전) 검사하지
  않는다. 판정 근거는 §1과 같은 `_skeleton-README.md` 자기감지다.

새 이력 파일을 만들지 않는다 — 이미 두 곳(README Changelog, workspace changelog)이 있고,
세 번째를 더하면 이 레포가 계속 싸워 온 이중 관리가 하나 늘어난다.

## 검토한 대안

**§8 직전 버전 소스**
- ✅ 채택: changelog → git tag 폴백 — 설정 없이 두 레이아웃 커버.
- ❌ 기각: changelog만 — `mobius4`(루트 `CHANGELOG.md`)에서 스킵. 사고 난 레포를 못 잡는다.
- ❌ 기각: git tag만 — 태그를 안 다는 프로젝트에서 무력화(스캐폴드 자신이 그렇다).
- ❌ 기각: changelog 경로를 설정 가능하게 — §5·§6까지 건드리는 큰 변경이고 설정 항목이 는다.
  자동 감지로 해결되는 문제에 설정을 도입하지 않는다(버전 SoT 자동 감지와 같은 판단).

**§8 판정 방식**
- ✅ 채택: 직전-버전 비교(습관 자동 감지).
- ❌ 기각: "SoT 버전이 README에 없으면 경고" 무조건 검사 — 버전을 README에 안 적는 프로젝트에서
  100% 오탐. 스캐폴드는 그런 프로젝트도 대상이다.
- ❌ 기각: `commands.md`에 `readme-version: required` 설정 플래그 — 설정하지 않은 레포는
  영원히 안 켜진다. 사고는 "설정을 깜빡한 레포"에서 난다.

**§9 필수 목록**
- ✅ 채택: README + CLAUDE.md(두 위치 중 하나).
- ❌ 기각: 자식 레포 원안(README·user-guide·how-it-works·CLAUDE.md 4종 고정) — 스캐폴드
  자신이 경고를 내고(`.claude/CLAUDE.md` 사용), DEC-009의 lazy 생성 규정과 모순된다.
- ❌ 기각: README만 — CLAUDE.md가 없으면 방법론 자체가 로드되지 않는다. 가장 크게 잘못된
  상태인데 그걸 놓친다.

**버전 스탬프**
- ✅ 채택: `.claude/SCAFFOLD-VERSION` + `/release` 동시 기록 + 템플릿 레포 한정 일치 검사.
- ❌ 기각: 스탬프 파일만(검사 없음) — 손으로 맞춰야 하는 순간 드리프트한다. 이 레포가 버전·
  changelog에서 이미 겪은 문제다(DEC-011).
- ❌ 기각: 스크립트 헤더 주석에 버전 — 갱신 지점이 여럿이라 버전이 여러 개가 된다.
- ❌ 기각: 전용 이력 파일(`SCAFFOLD-CHANGELOG.md`) 신설 — 이력이 세 곳이 된다.

## 리스크 / 고려사항

- **§8이 첫 릴리즈를 못 잡는다.** 구조적 한계다. 첫 릴리즈는 README 골격을 `/release`가
  삽입하고 §1(플레이스홀더)이 미작성을 잡으므로 다른 그물이 있다.
- **§9는 `_skeleton-README.md`가 있는 동안 꺼져 있다.** 스캐폴드 템플릿 레포 자신은 검사
  대상이 아니다. 부트스트랩에서 스켈레톤을 지우는 순간 켜진다(§1과 동일한 동작).
- **스탬프의 과거 값은 복원할 수 없다.** 이미 파생된 3개 레포는 자기가 받은 시점을 모른다.
  다음 동기화 때 그 시점의 값을 적어 넣는 것으로 시작한다(소급 추정하지 않는다).
- **`previous_git_tag()`는 shallow clone에서 빈 값**이다. 기존 `git_history_usable()` 가드를
  그대로 쓰므로 경고가 아니라 스킵이 된다. CI는 `fetch-depth: 0`이라 영향 없다.
