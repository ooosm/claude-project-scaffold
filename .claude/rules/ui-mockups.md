# UI 설계 게이트 — HTML 목업 우선 (UI Mockups)

> 방법론 구성요소 ② 프론트엔드 설계 시 HTML 목업 우선

## 게이트 규칙 (명문화)

**목업 검토 없이 UI 코드 작성 금지.**
UI 레이아웃이나 시각적 선택이 생기면, **터미널 ASCII가 아니라 self-contained `.html`
목업**을 만들어 사용자에게 보여주고 **승인받은 뒤** 구현한다.

## 절차

1. UI가 필요한 요구사항(FR)을 식별한다.
2. 단일 파일 `.html` 목업을 작성한다(인라인 CSS/JS, 외부 의존성 없이 브라우저로 바로 열림).
   - 저장 위치 권장: `docs/superpowers/specs/mockups/` 또는 spec 문서 옆.
   - 시안이 여러 개면 파일을 나눠 **나란히 비교**할 수 있게 한다.
3. 사용자에게 목업을 보여주고 레이아웃/흐름/시각 요소에 대한 승인을 받는다.
4. 승인된 목업을 **근거**로 실제 컴포넌트를 구현한다.
5. 선택·기각된 시안 사유는 **DEC 로그**에 기록한다(→ `decisions.md`).

## 목업 작성 원칙

- self-contained: 하나의 `.html`로 열리고, CDN조차 가급적 피한다(오프라인 검토 가능).
- 실제 데이터에 가까운 더미 데이터로 채운다(빈 껍데기 금지).
- 반응형/상태(hover·empty·error 등) 변형이 중요하면 함께 보여준다.
- 디자인 품질이 중요한 경우 frontend-design 스킬을 활용한다.

## 금지

- ASCII 박스 아트로 UI 레이아웃을 제안하고 그대로 승인받는 것.
- 목업/승인 없이 곧장 UI 컴포넌트 코드를 작성하는 것.
